# Era notes — 2014-2018 term (batches 66-95, Mayor Matt Brown era)

Fixer round 1 notes: this branch's remit is the 2014-2018 council term only
(window 2014-12-01 to 2018-11-30), for era-labeled career sections of
RETURNING councillors. Pre-2018 committee motion text is recovered from
Word-format eSCRIBE source (#202) and is ~99% boilerplate at committee
stage; Council roll calls are recovered directly. This round fixed one
BLOCKER, extended two sweeps whose hard-coded `ERA_BATCH_RANGE` silently
skipped this branch's own batches, widened one corpus-wide guard whose
motionText-only join was vacuous against boilerplate committee text, and
added one new permanent guard. Full detail is in `corrections.json`'s own
per-row `reason` fields; this file records the open questions and posture
that don't belong in a single correction row.

## BLOCKER: Tokala Trail (OZ-8511) — six rows reverted to axis=null

A prior "corpus-wide taxonomy fix" (grep of committed axis values,
defaulting every null-axis row to `application-approval` as "the dominant
catch-all") auto-promoted 5 batch-70 rows in the Tokala Trail rezoning
sequence (2015-10-27 Council item 7 / item XIII, 2605-2651 Tokala Trail)
from `axis: null` to `axis: application-approval`, leaving each row's
native, never-independently-reviewed `polarity: restrictive` standing.
That made four PASSED, YEA-approved motions (clause 7 as amended, first/
second/third reading and enactment of Bills 357/366 — Josh Morgan and Anna
Hopkins voting YEA on all four) render as "denied the development,
rezoning, or housing-policy item" for their own yea votes — backwards. A
sixth row (the amendment 42cba9ee91f2, native `application-approval`/
`expansive`, never touched by the taxonomy fix) directly contradicted its
immediate successor in the same sequence despite an identical 11-4 roster.
All six rows are now `axis: null` (see `corrections.json`, ids
`01ef42e8258d`, `1d7f4ec01410`, `680d0c7292ca`, `7c5b2a64db26`,
`11256244f4e4`, `42cba9ee91f2`) — reverting the taxonomy fix's
over-promotion for this specific sequence, matching its pre-fix (excluded)
state, which was the last state anyone actually verified against source
text.

**Open question for a future round:** the Tokala Trail sequence itself
(redesignating part of 2605-2651 Tokala Trail from Multi-Family Medium
Density Residential to an Office designation, with a parking-fee-permission
amendment along the way) is a real, substantive housing-supply-adjacent
decision that a human reviewer may want to hand-classify properly (rather
than leave null) — it was left null here because the taxonomy fix's
batch-wide promotion carries no per-motion textual re-derivation to trust,
not because the sequence is inherently unclassifiable.

## Two sweeps' hard-coded ERA_BATCH_RANGE (class fix)

`sweep-substitution-vs-final.py` and `sweep-levy-thousands-rounding.py`
both hard-coded `ERA_BATCH_RANGE = range(40, 66)` (the 2018-2022 term) —
inherited unmodified from the base branch — so neither ever read this
branch's own batches 66-95 and both passed vacuously. Re-pointed at
`range(66, 96)`; re-pointing surfaced:
- `2e7ac56e061a` (2016-05-31 Council item 2#4, Shift RT LRT-conversion
  clause): a genuine sweep false positive — the item's "balance of clause
  2, as amended" final vote explicitly EXCLUDES part b) (already voted
  separately, this id), so it never re-puts this clause's substance to a
  vote. Documented in the new `reviewed-substitution-pairs.json` rather
  than nulled; the transit-service/expansive classification stands.
- `30823f9db4dc` (2016-01-29 SPPC item 2, municipal golf multi-year
  operating budget line): the source item's own title states "rounded to
  the nearest $1,000s"; the row's `whatAYeaDid` printed the bare `$1`
  instead of the true `$1,000` figure — same 1000x-understatement class as
  the 2018-2022 era's own seed fix (`2d989f0d676e`). Corrected the dollar
  figure only; axis/polarity were already correctly null (a $1,000
  break-even/symbolic net amount, per the source-swap-$0 convention).

Both sweeps' self-tests targeted 2018-2022-era ids that are out of this
era's `ERA_BATCH_RANGE` entirely (their revert would never surface as a
hit here) — updated to target in-era ids/mechanisms instead, so the
negative test is no longer vacuous either.

## verify-cross-stage-consistency.py: quote-based join added

The guard joined committee/Council twins on `motionText` identity only.
634 of 701 committee-stage rows in this era have boilerplate motionText
("Motion Passed"/"Motion Failed"), so the join almost never fired here —
its "0 mismatches" was vacuous, not a clean bill of health. Added a second
join on each entry's own verified `quote` field (the pipeline's recovered
real text, present even when motionText is boilerplate). This surfaced two
genuine in-era mismatches, both corrected in `corrections.json`:
- `f480de5c2bdd`/`8985ed0ff68b` (195 Dundas Street T-54 zone extension):
  the committee side had been reclassified to `housing`/
  `application-approval`/`expansive` based on a "TZ-####" code visible
  only in the item TITLE — exactly what this era's rule bars ("never infer
  from the item title" when committee text is boilerplate). Reverted to
  null, matching the Council twin's already-correct null.
- `4411a0f0ddcc`/`66e1dd367654` (324 York Street T-71 zone refusal, Bradel
  Properties): the committee side's own `quote` and `whatAYeaDid` already
  correctly described a housing-application refusal, but issue/axis/
  polarity were left at none/null/null — an internal inconsistency, not a
  genuine boilerplate case. Corrected to match its own fields and the
  Council twin.

**Widening this guard's join also surfaced two mismatches entirely outside
this branch's own batches** (2022-04/05, batch 62/63; 2025-04/05/06,
batches 7/8) — real instances of the same defect class, left **unresolved
by this branch on purpose**: this branch's task explicitly forbids
changing any pre-2023 rendered row, and touching 2023+ data risks
colliding with that era's own in-flight branch. The guard now scopes
*resolution* (not detection) to this branch's own era batches and prints
out-of-era hits under OUT-OF-SCOPE so the owning era's own gate round
still sees them. **Handoff note for whoever runs the 2018-2022 or 2023+
gate next:** `02abcd162f8e`/`94424a190de9` and `b36ab4434a9f`/
`bcb9032d6ff0` are real, live cross-stage axis/polarity mismatches per this
guard — worth a look.

## New guard: sweep-duplicate-parsed-votes.py

Gate finding: 2015-01-29 SPPC item 2, roll-call ordinals 37/39/40
(`2ce9b0c30e4f`, `8472d08a14e3`, `5d09f101f7c3`) are ONE underlying FAILED

one more live, unresolved instance **outside this era** (`32b3a392fe5e`/
`cf6233c1dc64`, 2025-04-22), printed OUT-OF-SCOPE for the same
pre-2023-row / other-branch reason as above. **Handoff note:** that 2025
pair is a real, live double-count worth fixing on whichever branch owns
2023+ data.

## Minor: ed1101394ca0 quote scope
